# 社区、检测网站与论文复核 · 2026-10-27

## lm.ikale.io 是否值得参考

[lm-detector](https://github.com/Ikaleio/lm-detector) 本次页面约 973 stars、MIT 许可。它让模型生成整数序列，通过数字偏好寻找库内相似模型；项目明确说明库外模型也会得到最近候选，不能由此证明身份。

[原理文档](https://lm.ikale.io/docs/principles/)与[排名文档](https://lm.ikale.io/docs/principles/ranking/)说明了特征、留出环境校准及闭集概率的限制。可取之处是行为分布、多提示环境与独立校准；不应把归一化概率当作中转站“真货率”。

**已融合**：0.5.1 增加可选数字序列探针，保留本地统计和自己的官方参考，按整次请求配对做一个多变量检验。未复制其模型库、训练分类器、固定判别阈值或代理服务；不是其算法复现，也没有相同检出率保证。能力与行为结果分别显示，仍只面向 GPT/Claude。

**未加入分词器身份判断**：[该站文档](https://lm.ikale.io/docs/principles/tokenizer/)也提醒模型可能共用分词器，网关可能自行估算用量。它能提供接口计数层面的线索，但对“旗舰智力是否达标”并不直接有效，因此本轮保留已有 usage 记录，不为此额外增加几十次请求或身份阈值。

## 为什么不能给出“99% 就是真模型”

[Cai 等人的 API 替换审计研究](https://arxiv.org/abs/2504.04715)研究了随机替换、量化和规避评测等情况，指出文本统计及日志概率方法存在成本和可靠性限制，并讨论了需要供应商配合的可信执行证明。RelayLens 无法为任意中转站凭空增加这种证明。

[指纹伪装研究](https://arxiv.org/abs/2606.16100)展示了弱模型通过微调模仿指纹的风险。这与“偶尔写错一道题就一定是假模型”同样重要：相似行为不是权重证明，行为不同也可能由提示词、采样、预算、量化或代理层造成。

[OpenAI 评测指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices)支持围绕具体任务、自动评分和迭代评测。RelayLens 采用这些原则，具体题库和统计决策由本项目实现；并未集成或依赖其托管 Evals 服务。

## 本轮实际决策

1. **增加测量内容**：完整题库共 14 类，保留原标准 8 类；前后端语义题带本地标准答案，避免用另一模型的主观评价替代判分。
2. **增加能力参照**：允许多个已核实 GPT/Claude 报告逐个比较，所有匹配都展示，不能区分时明确保留歧义。
3. **修复误判入口**：严格 JSON 类型、重复键、输出完成标记、工具值精确匹配、参考重复记录及重复比较次数处理。
4. **保留来源差异**：网络错误、截断、格式错误、答错、参考不兼容分别展示。速度、文风与模型名称不独立决定真假。
5. **保留轻量运行**：本地 HTML 报告已能查看结果，无需另建 Web 后端。完整网页视觉质量和大型代码库开发能力仍不在这套题的已验证范围。
6. **不捏造基线**：本轮软件测试使用确定性本地求解器和模拟 HTTP 服务，未采集新的付费官方模型成绩。需要真实官方/中转配对实测，才能估计对具体型号的检出率、误报率和难度区分度。

## 复测方法

先固定题库版本、任务配置、margin 和 seed，在官方及中转各跑一次；更换未看过的 seed 再独立复测。不要看完结果再挑有利题目或阈值。把高、中、低预期能力的多个官方型号作为锚点；如果全部满分，继续增加独立难题，而不是把相同分数称为同一模型。不同时间重复可以观察变化，但当前面板不是完整的时间序列变点检测器。

参考源分别使用各自的官方 Key；仅由中转站生成的“官方参考”不能成为已核实官方基线。官方 `high` 在不同型号上也不代表完全相同的内部计算量；报告结论始终只对所选调用设置成立。

## 2026-10-28：少量题、目标等级与“账号降智”

- [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) 强调任务相关、贴近实际分布的数据与明确评分规则，避免泛化分数替代实际用途。采用：目标型号与同配置参考配对，保留私有/留出题；不采用用另一模型自评给“真货概率”。
- [Position: Don't use the CLT in LLM evals with fewer than a few hundred datapoints](https://arxiv.org/html/2503.01747v2) 讨论小样本下常规正态近似和 bootstrap 可能低估不确定性。采用：不把 8/16 道全对解释成目标认证；bootstrap 仅描述，正式结论继续用保守有界差距/精确二项上界。16 题只是减少单题影响，不是论文保证的充分样本量；生成题族相关性仍限制外推。
- [OpenAI Reasoning guide](https://developers.openai.com/api/docs/guides/reasoning) 说明 reasoning effort 会影响推理投入，输出预算还包含推理 token。采用：保留 high、充足预算与截断证据；仅接受参数不能证明中转真的执行了参数。
- [OpenAI Rate limits](https://developers.openai.com/api/docs/guides/rate-limits) 描述吞吐限额、用量等级及 429/503 错误；[模型选择说明](https://learn.chatgpt.com/docs/models) 解释型号与思考档。上述资料没有为“官方秘密降低特定账号智商，因此中转很便宜”提供证据。软件不能从价格、速度或两次不同题分数诊断账号状态；实际路由、额外提示、思考预算等需独立证据。没有发现证明不等于已经排除所有供应商行为。

0.8.0 不改变答错的事实：只有唯一且完整正确的内容才计通过，严格格式原分保留，分项分仅解释错在哪里。目标 S 必须有可信的同题配对优势；A 表示在预设容差内，不是 100% 身份保证。没有可靠目标参考显示 U/未验证，避免把题库容易或偶然满分误包装成达到所选型号。
